## The Cost of Being Right in Advance

A query optimizer's job is to guess, before a single row moves, how the rest of the query will behave: whether a given join order avoids a monstrous intermediate result, whether an index is actually selective, whether one side of a join is small enough to build a hash table from. The guess happens once, against statistics that are themselves guesses about a table's current state, and the resulting plan then runs to completion regardless of what the guess turns out to have been worth. Adaptive re-planning, the family of techniques that let an engine watch what actually happens partway through execution and revise the plan in response, is the obvious answer to a system built on prediction under uncertainty. Across most production query engines it survives instead as a secondary feature, present in some limited form but rarely the object of new research or of the benchmarks that determine what a good query engine is taken to mean.

Static plan quality is far easier to measure than adaptive value, and it is this gap in measurability, more than any gap in importance, that has shaped what the field rewards. Give an optimizer a fixed schema and a fixed data distribution against a single fixed query, and the actual optimal plan can be computed by brute force, compared against what the optimizer chose, and reduced to a ratio that means something on a slide. The comparison is clean because everything about the workload is frozen at the moment the plan is generated (frozen data, frozen query, no drift), which is exactly the condition under which a static plan is least likely to fail. Cardinality misestimation, correlated columns, skewed joins, a batch job that reshapes a table between the optimizer's last statistics refresh and the query that runs against it: none of this appears in a benchmark built to hold the world still long enough to grade a plan against it.

Adaptive re-planning earns its keep precisely in the cases a static benchmark is built to exclude, which is why its value is nearly invisible to the instruments the field uses to decide what matters. A system that re-plans well shows nothing extra on the query where the initial estimate was already close; its contribution appears on the query where the estimate was wrong in a way nobody had written a test for, where the difference is between a plan that finishes and one that spills to disk and has to be killed by an operator. That difference cannot be reduced to a percentage improvement over a baseline; it shows up, if it shows up at all, as an incident that did not happen, and an incident that did not happen is a hard thing to put in a benchmark and an easy thing for a research agenda to overlook.
